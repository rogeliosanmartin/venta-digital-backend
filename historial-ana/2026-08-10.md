# ANA — 2026-08-10 — Backend Venta Digital

## Objetivo del día

Soportar la integración con Odoo (asociación de cliente y generación de
cotización) sin afectar la captura de la venta, y mover Google Drive a config
apta para producción.

## Integración Odoo

- Entidad `Sale`: nuevas columnas
  - `odoo_partner_id` (`res.partner` ligado por CURP desde Odoo).
  - `odoo_sale_order_id` (`sale.order` generado desde conciliación).
- DTOs `SetOdooPartnerDto` y `SetOdooSaleOrderDto`.
- Endpoints de integración (protegidos por `X-Api-Key`):
  - `PATCH /api/integrations/odoo/sales/:id/partner`
  - `PATCH /api/integrations/odoo/sales/:id/sale-order`
- `sales.service`:
  - `setOdooSaleOrder` valida que exista `odooPartnerId` y evita sobrescribir
    con `ConflictException` si ya hay una cotización distinta ligada.
  - `listForConciliation` expone `odooPartnerId` / `odooSaleOrderId`.
- `saleToPublic` incluye los nuevos ids.
- **Regla:** estas relaciones son solo trazabilidad Odoo → VD; no alteran el
  flujo de captura ni el estado de la venta en el front.

## Google Drive (producción)

- Se prioriza `GOOGLE_SERVICE_ACCOUNT_JSON` (contenido del JSON en variable de
  entorno / secret) sobre la ruta a archivo local, pensando en Kubernetes/AWS.
- `.env` y `.env.example` actualizados; `GOOGLE_SERVICE_ACCOUNT_PATH` queda solo
  para desarrollo local.
- Mejora de estructura de carpetas para documentos de ventas en Drive.

## DB / migraciones

  `ALTER TABLE vd_sales ADD COLUMN odoo_partner_id int NULL;`
  `ALTER TABLE vd_sales ADD COLUMN odoo_sale_order_id int NULL;`
