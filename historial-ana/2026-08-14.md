# ANA — 2026-08-14 — Backend Venta Digital

## Objetivo del día

Dejar de usar **conciliación** como destino de la venta. VD guarda en su BD
y manda **expediente virtual** a Odoo con el payload completo.

## Flag de sync

- Columna `odoo_reception_synced` (boolean) en `sales`.
- Indica si el expediente ya está en Odoo.

## Sync expediente

- Tras finalizar venta: POST/upsert expediente en Odoo (api-odoo-gsm →
  `sale.order.reception`, `file_type=virtual`).
- Se re-sincroniza al registrar **pago** (ticket) y al **firmar**.
- Límite de body subido (INE/PDF): ajustar proxy gsm si `request entity too large`.

## Odoo (`sale_order_reception`)

- Expediente recibe los mismos datos que tenía conciliación.
- Tipo default **virtual** si viene de Venta Digital.
- Vista reorganizada: contacto = cliente Odoo; titular sustituto ≠ contacto.
- Adjuntos: nombre de archivo **como en Drive** (no URL suelta + duplicado).
- **Generar cliente / Generar cotización** usan datos del expediente, no
  vuelven a pedir el payload a VD.
- Sí se notifica a VD: `odooPartnerId` y `odooSaleOrderId` al ligar.

## DB (`DB_SYNC=false`)

```sql
ALTER TABLE sales ADD COLUMN odoo_reception_synced BOOLEAN NOT NULL DEFAULT false;
```
